## 二、阶段 1：小说导入（详细设计）

### 2.1 官方行为规格（自反混淆产物 `deob-novel/deobfuscated.js` 696 行提炼）

**主入口** `generateNovelImportResult(input) → result`：

| 输入字段 | 类型/默认值 | 校验 |
|---|---|---|
| `rawNovel` | string | 必填，清洗后非空；长度上限常量（实现时从产物 `index-SIF0oviY.js` 的 `a6` 导出再提取精确值） |
| `model` | string / 当前 chat 模型（兜底 `gpt-5.4`） | — |
| `language` | string / `中文` | — |
| `targetDuration` | string / `60s`；预设 `30s/60s/120s/300s`，也接受 `90s/3m/2m30s/2:30`（复用 `parseDurationToSeconds`） | UI 校验：无效格式报错 |
| `desiredEpisodeCount` | number / 空（自动拆分） | 1~24 整数，否则报错 |
| `seriesTitle` | string / 空（LLM 自拟） | — |
| `abortSignal` / `onProgress` | 中断与进度回调 | — |

**输出**：`{ projectTitle, projectDescription, seriesTitle, episodes[], model, language, targetDuration, sourceSectionCount }`，每集 `{ episodeNumber, title, summary, hook, rawScript, sourceSectionIds }`。

**五步流水线**（每步均有 LLM 失败时的确定性降级，保证永远有产出）：

1. **结构整理**（纯函数，无 LLM）：按章节标题正则切分
   （`第[\d一二三…]+[章节回卷部篇集]`、`chapter N`、`序章/楔子/前言/尾声/番外/后记`，忽略大小写）；
   无章节标题时按空行分段，再按字符预算聚合（超预算段切为「标题（2/3）」续段）；
   分段目标大小自适应：`clamp(总字符/预期段数, 2800, 7000)`。
2. **片段摘要**（并发 2）：每段一次 LLM 调用（prompt「小说拆分助手」，严格 JSON：
   `summary 80-180字 / keyEvents 2-5 / characters / hook`；temp 0.25 / 1600 tokens /
   json_object / 300s 超时 / 重试 2 次隔 1200ms）；失败降级为启发式摘要
   （前两段拼摘要、前三句做关键事件、末段做钩子）。
3. **多层压缩**（仅当摘要节点 > 上限时）：节点上限 = `clamp(集数×2, 8, 24)`；
   逐层分组（每组 `clamp(⌈n/max⌉, 2, 6)` 个节点）压缩为高层剧情阶段
   （prompt「小说结构编辑助手」，temp 0.2 / 1400 tokens）；失败降级为确定性合并
   （标题拼接、摘要拼接 220 字、事件去重取 6、角色去重取 8）。
4. **分集规划**（一次 LLM 调用）：prompt「资深小说改编策划」，严格 JSON 输出
   `projectTitle / projectDescription / seriesTitle / episodes[]`（硬性要求：恰好 N 集、
   `sourceSectionIds` 只能用给定 id、按原文顺序、每集有开场任务/冲突升级/结尾钩子、
   高潮不堆最后一集）；temp 0.3 / 4096 tokens / 重试 2 次隔 1500ms。
   失败降级为等分算法（按节点均分 N 集取摘要/钩子/焦点）。
   结果校验：集数过滤、`episodeNumber` 夹取 1~24、id 白名单过滤并按原序排序、
   逐字段回退到等分结果；最后把高层节点 id 展开回原始 section id。
5. **逐集草稿**（**串行**，保证连续性）：每集一次 LLM 调用（prompt「短剧编剧」，
   `rawScript` 要求纯文本、场景标题 + 动作/对白格式、开场承接上集、结尾留钩子、不写占位词；
   temp 0.45 / 4096 tokens / 重试 2 次隔 1500ms）。连续性上下文：上一集摘要/悬念/
   结尾片段（600 字截断）、本集开场素材重点、下一集承接方向。原文素材按 18000 字符预算
   组装（每段带标题/摘要/关键事件/原文 7000 字截断）。失败降级为素材拼接
   （「场景N：标题 + 摘要 + 关键事件」）。

**时长档案**（决定每集字符/段数/草稿长度，预设 + 秒数线性插值）：

| 时长 | 每集源字符 | 每集段数 | 草稿长度 | 节奏提示 |
|---|---|---|---|---|
| 30s | 4500 | 1.2 | 1200-1800 字 | 极快节奏，单一冲突 |
| 60s | 7500 | 2 | 2200-3200 字 | 快节奏，结尾悬念 |
| 120s | 13000 | 3.5 | 3600-5200 字 | 中快，完整起承转合 |
| 300s | 22000 | 6 | 6500-9000 字 | 中等节奏，充分铺垫 |

集数预估（未指定时）：`clamp(max(⌈总字符/每集字符⌉, ⌈段数/每集段数⌉), 1, 24)`。

**UI 交互规格**（自主 bundle 68250-68420 行文案提取）：粘贴正文或上传 `.txt/.md` →
必填单集时长 → 可选集数（1-24 或留空自动）→ 可选剧集名 → 语言（默认中文）→
进度展示（「正在整理小说结构…」「正在提炼片段 i/N：标题」「正在规划 N 集结构…」
「正在生成第 i/N 集草稿」）→ 结果预览 → 「继续导入」。落地方式二选一：
新建系列下的 N 个项目，或「复用现有集数作为新分集草稿」（覆盖前弹「高风险操作确认」）。

  素材面板（生图/生视频结果入轨）；
- UI 定位建议：**交互自设计、功能对齐**（L3）——不逐像素复刻官方 workflow 布局，
  但功能清单与接口行为对齐；主 bundle 反混淆产物仅在需要理解官方交互意图时查阅；
- 模块初划：`components/cutos/`（工作台页面、时间线、素材面板、Agent 对话面板）+
  `services/cutos/`（流式客户端、工具参数封装）——文件数较多，实施时按 ≤8 文件/层细分；
- 预估 1~2 周，建议阶段 1 完成后先出独立细化方案再开工。
